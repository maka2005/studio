# Приёмка и коммерческий запуск

Проверка от 29 октября 2026. Проект в этом сеансе подключён к рабочим Supabase и Vercel проектам.

## Проверено
- `npm run build`: успешно (TypeScript и production-сборка Vite).
- `node --experimental-strip-types --test supabase/functions/notify-dispatch/format.test.ts`: тесты форматирования уведомлений.
- Публичный endpoint клиентского Telegram проверен без действительного токена записи: корректно отклоняет запрос как `booking_unavailable`.
- Supabase применил миграции `customer_telegram_opt_in` и `customer_telegram_reminder_schedule`; таблицы ссылок и RPC созданы. У `anon` нет права создавать клиентские ссылки; RPC доступен только `service_role`.
- Расписание `notify-dispatch` активно; вызовы функции возвращают HTTP 200. Уведомления студии используют очередь с повторами.
- Vercel и Supabase Edge Functions выпускаются отдельно: Edge Functions развернуты напрямую в Supabase, сайт публикуется через GitHub → Vercel.

## Перед включением клиентских Telegram-уведомлений
- Проверьте/перевыпустите токен бота, если он когда-либо попадал в переписку или публичные логи; обновите Supabase secret и webhook.
- Подключите студийный чат и отправьте тестовую запись.
- В кабинете включите клиентские уведомления, затем выполните тестовую запись, согласитесь на Telegram, откройте бота и нажмите «Запустить». Проверьте подтверждение, отмену и напоминание. Клиентская функция по умолчанию выключена.

## Что остаётся перед продажей клиентам
- Текущий tenant `graphite` всё ещё в статусе `preview` с демо-флагом. Не переводить в `live`, пока не заменены демонстрационные данные, юридические реквизиты, расписание и контакты.
- У проекта пока нет автоматического онбординга/создания tenant и биллинга: подключение новой студии выполняется вручную. Это подходит для продажи проекта с настройкой под клиента, но не для самостоятельного SaaS-онбординга.
- Нужны настоящие домен и реквизиты оператора для каждого клиента; текущие юридические данные нельзя считать готовыми к публикации без проверки владельцем бизнеса.
- Не выполнялся end-to-end тест реального клиентского сообщения в Telegram, поскольку он отправляет реальные сообщения и требует безопасно перевыпущенного bot token.
- Supabase Security Advisor продолжает показывать 31 доступную authenticated SECURITY DEFINER функцию и предупреждение о выключенной проверке скомпрометированных паролей. Функции владельца проверяют членство tenant, а публичный просмотр опубликованных отзывов намеренный; всё равно следует завершить ручной аудит RPC и включить защиту паролей перед масштабным SaaS-запуском.
- Расширения в `public` и индексы, которые пока не использовались, отмечены Advisor как рекомендации; последние могут стать полезны при росте данных.
