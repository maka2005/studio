# Servio — платформа подписок (MVP)

Статус работ по ТЗ. Фронтенд прошёл локальные `npm run build` и проверку TypeScript. Миграции и Edge Functions не развёрнуты и не проверены на живой базе. Сначала применяйте на тестовом проекте Supabase или ветке, не на production.

## Принятые допущения (можно поменять)
| Вопрос | Принято | Где менять |
|---|---|---|
| Цена PRO | 25 000 ₸/мес (START 15 000) | админка → Тарифы |
| Существующая организация graphite | бессрочная подписка тарифа LEGACY, статус active | миграция `…platform_core.sql` |
| Trial / Grace | 14 / 5 дней | админка → Настройки |
| Организация без подписки | считается открытой (обратная совместимость) | `tenant_access_state` |

## Что сделано
**Этап 1 — база и безопасность** (`supabase/migrations/20261110100000_platform_core.sql`)
- Таблицы: `platform_admins`, `plans`, `subscriptions`, `subscription_events`, `saas_payments`, `platform_audit_logs`, `platform_settings`, `platform_requests` (ключи идемпотентности).
- RLS включён везде, политик нет, права у `anon`/`authenticated` отозваны: доступ только через `service_role` (Edge Functions).
- Изменение существующей таблицы: `tenants.created_at` (необязательное поле); статус организации не меняется.
- Правила доступа в БД: `tenant_access_state` (open / grace / closed считается по датам, а не только по статусу), `tenant_booking_open`, `tenant_notifications_open`, `owner_subscription`.
- Триггер `bookings_subscription_guard`: клиентская запись в организацию с закрытым доступом отклоняется на уровне БД, даже при прямом вызове функций. Владелец и менеджер не затрагиваются.

**Этапы 2–3 — админка и действия**
- `supabase/migrations/20261110110000_platform_admin_rpc.sql`: дашборд, списки, карточка организации, создание организации (одна транзакция + идемпотентность), действия с подписками (extend, change_plan, set_dates, suspend, resume, cancel), платежи (создать, подтвердить, не прошёл, возврат с причиной), настройки, тарифы (удаления нет), экспорт, ночная синхронизация статусов (pg_cron).
- `functions/platform-admin`: проверка JWT, записи в `platform_admins` и MFA (aal2) на сервере, лимиты, создание владельца через Auth Admin API (существующий email привязывается, дубликат не создаётся), письмо для установки пароля.
- `functions/tenant-export`: ZIP с CSV (записи, клиенты, услуги, отзывы, платежи студии), защита от formula injection, запись в журнал, работает в статусе suspended.
- `src/pages/PlatformAdmin.tsx` (`/platform/admin`): вход, MFA, дашборд, организации, карточка, создание, подписки, тарифы, платежи, журнал, настройки.

**Этап 4 — правила доступа**
- `public-api` (слоты, лист ожидания, новое действие `booking_status`), `booking-create` и `notify-dispatch` проверяют подписку на сервере. Публичная страница показывает «Запись временно недоступна». В кабинете владельца баннер grace/suspended.

## Как применить
1. Применить миграции по порядку (`…platform_core`, затем `…platform_admin_rpc`). Для расписания нужен включённый `pg_cron` (он уже нужен для уведомлений).
2. Секреты функций: `supabase secrets set PLATFORM_SUPERADMIN_EMAIL=you@example.com PLATFORM_REQUIRE_MFA=false` (включить `true` после настройки MFA). `SITE_URL` уже должен быть задан.
3. Развернуть: `supabase functions deploy platform-admin tenant-export public-api booking-create notify-dispatch`.
4. Первый вход: зайти на `/platform/admin` под пользователем из `PLATFORM_SUPERADMIN_EMAIL`. Либо выполнить `supabase/seed/platform_test.sql` (подставить email), он добавит суперадмина и 5 тестовых организаций: активная PRO, trial, истекает через 3 дня, grace, приостановлена.
5. Включить MFA: страница сама предложит настроить TOTP; затем `PLATFORM_REQUIRE_MFA=true`.

## Известные ограничения и что осталось
- Платформенная админ-сессия пока хранится в browser storage Supabase. Для снижения XSS-риска её следует перевести на HttpOnly-cookie прокси; service role key в браузер не передаётся.
- `get_slots` по-прежнему напрямую доступна `anon` (как и раньше): она отдаёт только свободные слоты, запись закрыта триггером и проверками в функциях.
- SMS в проекте нет, отключаются только Telegram-уведомления.
- Не сделано из ТЗ: публичная страница тарифов с формой заявки (вторая очередь), документ юридической части.
- SQL и Edge Functions нужно отдельно проверить на тестовой базе. MFA становится обязательной для админских операций после установки `PLATFORM_REQUIRE_MFA=true`.

## Чек-лист приёмки (из ТЗ, что проверить руками)
- graphite: запись, кабинет, Telegram, отзывы работают как раньше.
- Новая организация создаётся из админки; повторный клик не создаёт дубликат (один ключ на форму).
- Владелец A не видит данные B; обычный владелец получает 403 на `/platform/admin`.
- `demo-suspended`: запись закрыта (страница и прямой вызов `booking-create`), Telegram не уходит, кабинет открывается.
- Платёж → «Подтвердить» → «Возобновить» возвращает доступ.
- Экспорт работает для приостановленной организации.
